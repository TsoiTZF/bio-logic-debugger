## 1 软件概述

### 1.1 软件名称与版本

全称：育种目标生物逻辑验证系统  
简称：Bio-Logic Debugger  
版本：V1.0  
别名：让邺城燃烧（宣传用名，不作为登记全称）

### 1.2 开发目的

作物育种在确定目标组合时，容易同时提出相互拮抗或超出生理限度的指标，导致后续试验投入浪费。本软件在播种和杂交方案确定之前，根据已收录的性状关联、生理约束和历史反模式，对用户给出的目标组合做预筛，并输出可阅读的验证报告。

### 1.3 运行环境

- 硬件：通用微型计算机，建议内存 4 GB 及以上  
- 操作系统：Windows、Linux 或 macOS  
- 运行库：Python 3.10 及以上  
- 主要依赖：Streamlit（图形界面）、httpx（网络请求）、PyMuPDF（PDF 文本提取）、Pillow（图像）  
- 网络：本地即可完成规则验证；社区同步、DOI 检索、大模型分析需要外网

### 1.4 安装与启动

在软件目录执行：

```
pip install -e .
```

启动图形界面：

```
streamlit run bio_logic_debugger/app.py
```

浏览器访问本机地址（默认 http://localhost:8501）。

启动命令行：

```
bld
```

或：

```
python -m bio_logic_debugger.cli
```

单次验证示例：

```
bld --validate rice_yield_per_plant >= 50
```

## 2 软件结构

软件分为四层。

1. 领域层：定义性状、性状关联、生物学约束、反模式、育种目标、违反记录、验证报告。  
2. 引擎层：按固定顺序执行验证管线，生成报告。约束层对条件表达式求值。  
3. 知识层：从内置 JSON、社区缓存 JSON、用户扩充数据合并知识，并提供论文分析与同步。  
4. 界面层：图形界面入口只负责页面配置和导航；各功能页独立模块；命令行提供同等验证能力。

模块对应关系：

- `core/domain.py` 数据模型  
- `core/engine.py` 验证引擎  
- `core/expr.py` 约束表达式  
- `core/anti_pattern.py` 反模式匹配  
- `knowledge/builtin/` 内置知识 JSON  
- `~/.bio-logic-debugger/community/` 社区同步缓存（用户目录，不进安装包）  
- `knowledge/knowledge_store.py` 加载与合并  
- `ui/runtime.py` 引擎缓存与侧边栏  
- `ui/pages/` 各功能页面  
- `cli.py` 命令行  
- `llm/reasoner.py` 可选大模型分析

## 3 功能说明与操作

### 3.1 侧边栏与知识库状态

启动后左侧显示软件名称、版本、导航和知识库状态，包括是否已同步社区数据、性状/关联/反模式数量。需要时点击「检查更新」从社区仓库拉取 JSON 到用户目录缓存。启动时不会自动同步，同步不覆盖内置知识目录。

【截图 3：侧边栏导航与知识库状态】

### 3.2 育种目标验证

在导航中选择「育种目标验证」。

1. 填写育种目标名称。  
2. 按分类筛选性状，选择性状、方向（≥、≤、=）、目标值和优先级，点击「添加目标」。可多次添加。  
3. 需要时在「LLM 深度分析」中填入接口地址与密钥。不填写则只运行规则管线。  
4. 点击「运行验证」。  

右侧显示结论，分三档：可以推进、谨慎推进、不建议按原目标推进。仅致命级违反否定推进。同时给出致命、严重、警告、提示计数。下方展开每条问题：涉及性状、机制、叙事说明、建议。若匹配反模式，报告中单独列出历史失败途径和替代方向。

### 3.6 文献与知识库

选择「文献与知识库」，含三个分页。

**导入文献分析**：可上传 PDF，系统提取文本；或输入 DOI、标题检索论文元数据与摘要。可选上传图表供大模型解读。可从知识库关键词批量检索文献，勾选后抽取性状、关联、约束。抽取结果需人工勾选，再导入当前引擎，并记入用户扩充列表。

**知识库管理**：显示内置、社区、用户三类条目数量，可手动同步社区库，可导出用户扩充为 JSON。可对性状、关联、约束的置信度权重进行调整并保存，保存后重新加载引擎。

**贡献指南**：说明将导出 JSON 提交到社区知识仓库的步骤。

## 4 验证逻辑说明

### 4.1 基础检查

若目标中的性状不在知识库，写入建议并跳过与该性状相关的检查。若目标值超出该性状典型范围，记范围类违反；低置信度性状的范围问题降为提示。

### 4.2 关联检查

仅考察与当前目标相关的关联。负相关或权衡且双方都在追优时，按 |r|×置信度给出警告，最高为警告，不标致命。正相关在同向追极端时提示联动，一优一劣时提示顺风。曲线关联给出配比提示。区间方向不视为自动追高。有效强度低于阈值的条目跳过。

### 4.3 约束检查

将目标中已给出数值的性状代入条件表达式。表达式为真则记录违反；表达式为空、语法错误、嵌套过深或存在未绑定变量则跳过。语法错误写入运行日志，不把「提到该性状」当作违反。抗病抗逆采用 IRRI SES：1 为高抗，9 为敏感。

### 4.4 反模式匹配

计算目标性状集合与反模式触发性状集合的重合程度，并核对应性状是追优还是追劣。精确匹配或部分匹配且分数达到阈值时，写入反模式及建议替代方向。弱匹配只进入建议列表。优质籼稻（高产、长粒、高直链）不会仅因性状同时出现而被打成高产低质。

### 4.5 报告

结论只按致命级违反否定推进。存在严重级违反或命中反模式时为谨慎推进，其余为可以推进。报告可生成全文叙事，并可序列化为 JSON。

## 5 知识库

内置知识位于软件包内 `knowledge/builtin` 目录，包括性状、关联、约束、反模式四类 JSON。社区同步写入用户目录下的 community 缓存，不覆盖内置目录。合并时内置打底，社区只新增，用户扩充可覆盖同标识。水稻示例库规模约为：性状 40、关联 30、约束 10、反模式 8。数据来源包括国际水稻研究所品质评价思路、国家标准优质稻谷相关指标、以及公开的产量构成与抗逆研究，具体条目在知识文件的 evidence 字段中列出。

## 6 使用限制

1. 本软件给出的是基于当前知识库的逻辑预筛，不能替代田间试验、品种审定或专业鉴定。  
2. 未配置网络时，社区同步、DOI 检索和大模型分析不可用，本地规则验证仍可用。  
3. 建议在受信任的本机或内网使用。将接口密钥填入界面时，注意勿提交到公开仓库。

## 7 命令行参数

- `--list-traits` 列出性状。
- `--trait <id>` 查看单个性状及关联。
- `--list-patterns` 列出反模式。
- `--validate <id> <方向> <数值>` 单次验证。
- `--env KEY=VAL` 附加环境变量，例如 `drought_severity=severe`。环境键若与性状标识相同，以目标为准，不覆盖。
- `--json` 以 JSON 输出报告。
- `--interactive` 或不带参数进入交互控制台。

## 8 界面字段说明

育种目标验证页主要字段：目标名称、性状分类、性状、比较方向、目标值、优先级、环境变量（干旱程度、温度、施氮量）、可选大模型地址与密钥、运行验证按钮。结果区含结论、四级计数、问题展开区。性状浏览器按分类列出标识、名称、范围、单位、方向（越高越好或越低越好）。约束页按致命、严重、警告分档展示表达式。文献页默认不勾选抽取结果，需用户确认后入库，且不覆盖已有性状标识。

## 9 典型验证示例

示例一：株高 ≥130 且抗倒伏 ≤2（SES 高抗）。系统应给出致命级「高秆与高抗倒伏不可兼得」，结论为不建议按原目标推进。

示例二：仅株高 ≥130，不设抗倒伏。因约束缺少绑定变量，该致命规则不触发。

示例三：株高 ≥130 且抗倒伏 ≥7（易倒）。符合茎秆力学，不触发该致命规则。

示例四：有效穗 ≥22、每穗粒数 ≥300、千粒重 ≥33。触发产量三要素警告，结论一般为谨慎推进或可以推进，不升为致命。

示例五：亩产、粒长、直链淀粉同时走高（优质籼稻方向）。不因性状同时出现而匹配「高产低质」反模式。

## 10 知识条目字段

性状含标识、名称、单位、典型范围、是否越高越好、别名。关联含两个性状标识、类型、强度、置信度、机制、证据。约束含标识、名称、严重度、条件表达式、后果、证据。反模式含触发性状、意图（追优或追劣）、历史案例、替代方向。证据没有可核对链接时不标为已确认。相关系数在示例库中为示意量级。

## 11 常见问题

问：没有配置大模型能否使用？答：能。规则管线不依赖网络与密钥。

问：社区同步会不会改掉内置规则？答：不会。社区只追加新标识，用户扩充才可覆盖同标识。

问：结论为谨慎推进是否表示失败？答：不是。仅致命级表示不建议按原目标推进。

问：本软件能否代替品种审定？答：不能。输出是基于当前知识库的逻辑预筛。
