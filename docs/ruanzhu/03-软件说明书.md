## 1 软件概述

### 1.1 软件名称与版本

全称：育种目标生物逻辑验证系统  
简称：Bio-Logic Debugger  
版本：V1.0  
别名：让邺城燃烧（宣传用名，不作为登记全称）

### 1.2 开发目的

作物育种在确定目标组合时，容易同时提出相互拮抗或超出生理限度的指标，导致后续试验投入浪费。本软件在播种和杂交方案确定之前，根据已收录的性状关联、生理约束和历史反模式，对用户给出的目标组合做预筛，并输出可阅读的验证报告。

### 1.3 运行环境

- 硬件：通用微型计算机，建议内存 4 GB 及以上  
- 操作系统：Windows、Linux 或 macOS  
- 运行库：Python 3.10 及以上  
- 主要依赖：Streamlit（图形界面）、httpx（网络请求）、PyMuPDF（PDF 文本提取）、Pillow（图像）  
- 网络：本地即可完成规则验证；社区同步、DOI 检索、大模型分析需要外网

### 1.4 安装与启动

在软件目录执行：

```
pip install -r requirements.txt
```

启动图形界面：

```
cd bio_logic_debugger
streamlit run app.py
```

浏览器访问本机地址（默认 http://localhost:8501）。

启动命令行：

```
python -m bio_logic_debugger.cli
```

单次验证示例：

```
python -m bio_logic_debugger.cli --validate rice_yield_per_plant >= 50
```

## 2 软件结构

软件分为四层。

1. 领域层：定义性状、性状关联、生物学约束、反模式、育种目标、违反记录、验证报告。  
2. 引擎层：按固定顺序执行验证管线，生成报告。约束层对条件表达式求值。  
3. 知识层：从内置 JSON、社区缓存 JSON、用户扩充数据合并知识，并提供论文分析与同步。  
4. 界面层：图形界面入口只负责页面配置和导航；各功能页独立模块；命令行提供同等验证能力。

模块对应关系：

- `core/domain.py` 数据模型  
- `core/engine.py` 验证引擎  
- `core/expr.py` 约束表达式  
- `core/anti_pattern.py` 反模式匹配  
- `knowledge/builtin/` 内置知识 JSON  
- `knowledge/data/` 社区同步缓存  
- `knowledge/knowledge_store.py` 加载与合并  
- `ui/runtime.py` 引擎缓存与侧边栏  
- `ui/pages/` 各功能页面  
- `cli.py` 命令行  
- `llm/reasoner.py` 可选大模型分析

## 3 功能说明与操作

### 3.1 侧边栏与知识库状态

启动后左侧显示软件名称、版本、导航和知识库状态，包括是否已同步社区数据、性状/关联/反模式数量。需要时点击「检查更新」从社区仓库拉取 JSON 到用户目录缓存。启动时不会自动同步，同步不覆盖内置知识目录。

【截图 3：侧边栏导航与知识库状态】

### 3.2 育种目标验证

在导航中选择「育种目标验证」。

1. 填写育种目标名称。  
2. 按分类筛选性状，选择性状、方向（≥、≤、=）、目标值和优先级，点击「添加目标」。可多次添加。  
3. 需要时在「LLM 深度分析」中填入接口地址与密钥。不填写则只运行规则管线。  
4. 点击「运行验证」。  

右侧显示是否建议推进，以及致命、严重、警告、提示计数。下方展开每条问题：涉及性状、机制、叙事说明、建议。若匹配反模式，报告中单独列出历史失败途径和替代方向。

【截图 5：验证结果摘要与致命/严重计数】

典型操作示例：SES 抗倒伏 1 为高抗、9 为易倒。株高大于 120 且抗倒伏 ≤3（真高抗）应触发「高秆与高抗倒伏不可兼得」。株高大于 120 且抗倒伏 ≥7（易倒）符合茎秆力学，不触发该 FATAL。仅设置株高、不设置抗倒伏时，因缺少绑定变量，该条也不触发。

### 3.3 性状浏览器

选择「性状浏览器」，按分类查看性状标识、名称、典型范围、单位和文字说明。可展开该性状相关的关联条目，查看相关系数、关联类型和机制摘要。

### 3.4 反模式库

选择「反模式库」，可按严重等级筛选。每条反模式包括说明、触发性状、生理机制、历史案例、失败尝试和推荐替代方向。

【截图 8：反模式展开页】

### 3.5 约束规则

选择「约束规则」，逐条查看名称、描述、适用范围、后果、条件表达式和置信度。条件表达式采用 `$性状标识 比较符 数值` 及 AND、OR、NOT 组合。

【截图 9：约束规则列表及表达式】

### 3.6 文献与知识库

选择「文献与知识库」，含三个分页。

**导入文献分析**：可上传 PDF，系统提取文本；或输入 DOI、标题检索论文元数据与摘要。可选上传图表供大模型解读。可从知识库关键词批量检索文献，勾选后抽取性状、关联、约束。抽取结果需人工勾选，再导入当前引擎，并记入用户扩充列表。

**知识库管理**：显示内置、社区、用户三类条目数量，可手动同步社区库，可导出用户扩充为 JSON。可对性状、关联、约束的置信度权重进行调整并保存，保存后重新加载引擎。

**贡献指南**：说明将导出 JSON 提交到社区知识仓库的步骤。

## 4 验证逻辑说明

### 4.1 基础检查

若目标中的性状不在知识库，写入建议并跳过与该性状相关的检查。若目标值超出该性状典型范围，记范围类违反；低置信度性状的范围问题降为提示。

### 4.2 关联检查

仅考察与当前目标相关的关联。当关联为负相关或权衡，且用户对两个性状都选择「越大越好」的方向时，按有效强度（绝对值×置信度）划分致命、严重或警告。曲线关联给出配比提示，不视为双高拮抗。区间方向不视为自动追高。

### 4.3 约束检查

将目标中已给出数值的性状代入条件表达式。表达式为真则记录违反；表达式为空、语法错误或存在未绑定变量则跳过。语法错误写入运行日志，不把「提到该性状」当作违反。

### 4.4 反模式匹配

计算目标性状集合与反模式触发性状集合的重合程度。精确匹配或部分匹配且分数达到阈值时，写入反模式及建议替代方向。弱匹配只进入建议列表。

### 4.5 报告

存在致命或严重违反时，报告结论为不建议按原目标推进。报告可生成全文叙事，并可序列化为 JSON，便于保存和外部系统读取。

## 5 知识库

内置知识位于软件包内 `knowledge/builtin` 目录，包括性状、关联、约束、反模式四类 JSON。社区同步写入用户目录下的 community 缓存，不覆盖内置目录。合并时内置打底，社区只新增，用户扩充可覆盖同标识。水稻示例库规模约为：性状 40、关联 30、约束 9、反模式 7。数据来源包括国际水稻研究所品质评价思路、国家标准优质稻谷相关指标、以及公开的产量构成与抗逆研究，具体条目在知识文件的 evidence 字段中列出。

## 6 使用限制

1. 本软件给出的是基于当前知识库的逻辑预筛，不能替代田间试验、品种审定或专业鉴定。  
2. 未配置网络时，社区同步、DOI 检索和大模型分析不可用，本地规则验证仍可用。  
3. 建议在受信任的本机或内网使用。将接口密钥填入界面时，注意勿提交到公开仓库。
