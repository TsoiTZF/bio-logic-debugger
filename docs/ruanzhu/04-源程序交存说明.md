# 源程序交存说明

按惯例交 **前 30 页 + 后 30 页**（每页不少于 50 行）。不足 60 页交全部。页眉统一：

`育种目标生物逻辑验证系统 V1.0`

最后一页应是文件正常结尾（例如模块收尾、`if __name__ == "__main__"`），不要停在函数半截。

当前仓库 Python 合计约四千余行，够抽 60 页。建议按下表顺序拼接，保证「前面是模型与引擎、后面是界面与入口」，审查时能看出完整软件而不是一堆 JSON。

## 建议作为前 30 页的文件（按顺序）

1. `bio_logic_debugger/__init__.py`  
2. `bio_logic_debugger/core/domain.py`  
3. `bio_logic_debugger/core/expr.py`  
4. `bio_logic_debugger/core/anti_pattern.py`  
5. `bio_logic_debugger/core/engine.py`（可截到验证管线中段）

这些页体现：数据结构、表达式、匹配、引擎主流程。不要把 `builtin/*.json` 当源程序首页。

## 建议作为后 30 页的文件（按顺序，从后往前够页为止）

1. `bio_logic_debugger/app.py`（入口，放在最末若干页，让最后一页落在文件末尾）  
2. `bio_logic_debugger/cli.py`  
3. `bio_logic_debugger/ui/runtime.py`  
4. `bio_logic_debugger/ui/pages/validate.py`  
5. `bio_logic_debugger/knowledge/knowledge_store.py` 后半（加载合并）

## 不建议放进交存正文的

- `knowledge/builtin/*.json`、`knowledge/data/*.json`：数据不是程序  
- `.github/workflows/`、测试夹具、截图  
- 含密钥的本地 `.env`

知识 JSON 可以在说明书里用文字描述规模和字段，不必整文件贴进源程序。

## 抽取时注意

- 去掉多余空行后再分页，避免一页凑不够 50 行  
- 保留必要注释（说明意图的注释有助于审查）  
- 页码连续：第 1–30 页、第 31–60 页  
- 申请表里的「源程序量」按交存当天的行数填写，不要抄本文旧数字  

你改完代码后，若文件增删较多，按同样原则重抽：前段仍是 `core/`，后段仍是 `app.py` / `cli.py` 结尾。
